# v0.4.2 — Backup safety and review policy fixes

## Changes

- Remove newly created empty backup directories when creation setup fails while releasing its guard, so the name can be retried after the stale guard is safely cleared.
- Omit raw manifest identities from prune logs, preventing manifest notes and extra fields from leaking into retained diagnostics.
- Make release fingerprints stable across LF/CRLF checkout conversion, require the nearest previous release tag, and reject shipped changelog entries duplicated under Unreleased.
- Require completed automated Codex review for the current PR revision, assessment of every finding, and explicit approval when review is unavailable. The rule also covers direct promotion of release candidates with a PR.

## Safety and compatibility

No configuration migration is required. Setup cleanup removes only an empty directory created by that attempt; pre-existing backups are preserved. Guard cleanup failures still report an error, and stale guards require confirmation that the owning operation has stopped before removal. Prune selection, confirmation, and deletion safeguards are unchanged.

The review gate is an operator requirement, not a required GitHub status check. Required repository validation remains mandatory.

## Install and verify

Install or update the globally available CLI:

```bash
npm install --global @dodefey/db-helper@0.4.2
```

Confirm the installed executable reports `dbh 0.4.2`:

```bash
dbh --version
```
